## Заметки

- Cargo - система сборка, менеджер пакетов
- Установка "cargo install sqlx-cli" для миграций
- Миграции: "sqlx migrate add -r foundation" (up, down)
- Чтоб пропустить тест нужно добавить метку: #[ignore]
- Проблема: OnceCell создает клиент один раз для всех тестов. Но каждый тест запускается в своем
  runtime. Когда первый тест завершается, его runtime может быть уничтожен, но Client (который внутри
  содержит свой runtime) остается в статической переменной.
  Когда второй тест вызывает get_test_server().await, он получает уже существующий клиент, но его
  внутренний runtime уже мог быть уничтожен после завершения первого теста.
- Copy-семантика работает для типов размер которых известен в стеке и типов у которых реализован trait Copy, и которые
  состоят из св-в которые тоже известны. Для других будет move-семантика. Но перемещение в др. блок не сработает.
- Cargo.toml - файл манифеста написанный разработчиком, описание зависимостей в широком смысле.
- Cargo.lock - содержит точную информацию о зависимостях, какая ревизия была использована для всех этих зависимостей, не
  должен ред-ся в ручную.
- Размещение файла с именем build.rs в корне пакета заставит Cargo скомпилировать этот скрипт и выполнить его
  непосредственно перед сборкой пакета.
- Cargo не очищает и не сбрасывает OUT_DIR между сборками.
- &str - строковый слайс, который ссылается на буфер со строкой, но ни как не управляет этим буфером. Компилятор
  помещает в сегмент данных/кода и там эта строка живет все время. Не занимается управлением памяти. Может принадлежать
  сегменту данных, так и куче (если это изначально String) или даже располагаться на стеке. str — не Sized, а &str —
  Sized. Известный и постоянный размер (указатель и длина).
- String - является собственником буфера, в котором содержится строка. Это технически обертка няд Vec<u8>. Этот буфер
  располагается в куче.
- Любой объект непримитивного типа должен иметь только одного владельца.
- Borrow-checker - механизм компилятора который отслеживает время жизни объектов.
- Передача по ссылке объектов называется одалживанием (borrowing).
- В любом месте кода для любого объекта может существовать либо только одна мутабельная ссылка, либо любое количество
  немутабельных ссылок. "let r1 = &mut s; let r2 = & s;" - так нельзя.
- Для примитивов, тк размер маленький и не владеют доп-ыми ресурсами, срабатывает копирование в местах смены владения.
- trait A : B { ... } // Трэйт A "наследует" трэйт B
- Если компилятор видит что у объекта есть трейт Copy (trait Copy: Clone {}) (это играет роль пометки/маркера), то
  вызывается Clone(). У примитивов он есть, а у др. нет. Поэтому срабатывает copy-семантика. Если в структуру добавить
  трейт copy, то тогда move не будет происходить, а будет вызываться clone.
- Fn замыкания только читают захваченное значение
  FnMut замыкания изменяют захваченное значение по мутабельной ссылке
  FnOnce замыкание уничтожает захваченное значение
- println!(), format!() - в итоге берут ссылки, а не значения, как бы туда не передавалось.
- impl<T> Holder<T> - реализуй обобщенный T (для всего блока), а связь в Holder-ом через T.
- "::<>" - прозвали турборыбой (turbofish).
- fn my_func<T: Трэйт>(v: T); fn my_func(v: impl Трэйт); - одно и тоже по сути. Но компилятор не позволяет написать
  замыкание, которое возвращает "impl Трэйт", а для дженерика позволяет. Также "impl Трэйт" синтаксис имеет существенные
  ограничения при описании обобщённых асинхронных функций, с которыми мы познакомимся позже.
- Option: .flatten() - преобразует Option<Option<i32>> в Option<i32>. Метод "and_then" работает как комбинация "map" (
  если есть что-то, то изменяется, иначе вернет None) и "flatten".
- Option, Result - комбинатор .unwrap_or(default_value).
- Итератор можно в конце развернуть в др. тип: .collect::<Vec<_>>();.collect::<HashSet<_>>(); и тд. Vector, HashSet,
  HashMap, LinkedList, BTreeMap, VecDeque.
- let sum = [1, 2, 3].into_iter().fold(0, |x, y| x + y); // sum = 6. Словно имеет внутри static переменную и в него
  сохраняет данные, после отдает.
- let sum = [1, 2, 3].into_iter().reduce(|x, y| x + y); // sum = Some(6)
- .filter_map() - принимает ф-ию которая возвращает Option. То что Some, вернет.
- .find() - принимает ф-ию, если возвращает true, то возращает число (Option).
- Надо разобраться с библой https://crates.io/crates/itertools
- Умный указатель представляет из себя класс, который не просто предоставляет доступ к данным по адресу, но и умеет
  автоматически очищать память, на которую он ссылается.
- Трейты Deref, DerefMut позволяют получить условно оригинальную (не)мутабельную ссылку. Если они реал-ны в объекте, то
  компилятор внутри вместо &obj подменяет на obj.deref(), так же и с deref_mut.
-
- Box: фактически это просто безопасная обёртка над указателем. Конструктор Box::new(значение) переносит значение со
  стека в кучу и возвращает объект Box, внутри которого содержится указатель с адресом объекта в куче. Если размер на
  этапе компиляции не известен, то надо в Box.
- Rc (Reference Counted) - объект хранящий в себе ссылку на данные и ссылку на счетчик в куче. При клонировании
  копируются ссылки, счетчик увеличивается на 1. Когда выходит из скоупа, то счетчик уменьшается. При нуле идет отчистка
  данных из кучи. Он не реализует DerefMut, поэтому не может изменять данные.
- Cell<T> — обёртка, которая позволяет заменять своё содержимое целиком (не модифицировать), безопасно и атомарно. Но не
  позволяет получать мут. ссылку и получить не мут. ссылку которая стала бы не действительна при замене значения в Cell.
  Можно объявлять без mut, т.к. изменения происходят атомарно. Защиты от гонки данных у него нет.
- RefCell<T> - дает возможность модифицировать значение по ссылке. Не является потоко-безопасным.
  let ref_cell = RefCell::new(1);
  let mut mut_ref: RefMut<'_, i32> = ref_cell.borrow_mut();
  *mut_ref = 5;
- Arc<T> (Atomically Reference Counted) - потоко-безопастная штука.
-
- https://github.com/awesome-rust-com/awesome-rust - сборник популярных крейтов
- src/bin - создаются сколько угодно других исполняемых главных файлов
- Ссылка на трэйт-объект — это просто пара указателей: первый — на сам объект, второй — на vtable. При этом vtable не
  содержит название или ID типа, только указатели на методы, указатель на деструктор (если таков имеется), а также
  информацию о размере и выравнивании.
- vec - v.dedup(); // удаляет рядом стоящие дубликаты
- LinkedList (двусвязный список) - в отличие от вектора, двусвязный список позволяет эффективно вставлять/удалять
  элементы в середину и начало списка. сложность O(n/2), в отличие от сложности O(1) у вектора.
- VecDeque - имеет сложность O(1). Хорошая замена для LinkedList.
- HashSet - обертка над HashMap.
- BTreeMap - хранит элементы в отсортированном по ключу порядке.
- BinaryHeap - самый верхний узел всегда содержит наибольший элемент.
- flush (std::io::write) записывает в буфер, а после сбрасывает данные в файл.
- trait Send - маркерный трейт, говорит о том что данные можно пересылать между потоками.
- trait Sync - маркерный трейт, автоматически создается компилятором для любого типа, если не мут-ую ссылку на тип (&T)
  можно безопасно использовать в разных потока.
