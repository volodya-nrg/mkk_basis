### Общее

Rust - статически типизированный язык для системного программирования. Он должен знать типы во время компиляции.
Есть бинарный (исполняемый файл) и библиотечный пакет.
Crate - это коллекция файлов исходного кода Rust, библиотечный пакет.
Copy-семантика работает для типов размер которых известен в стеке и типов у которых реализован trait Copy, и которые
состоят из св-в которые тоже известны. Для других будет move-семантика. Но перемещение в др. блок не сработает.
Размещение файла с именем build.rs в корне пакета заставит Cargo скомпилировать этот скрипт и выполнить его
непосредственно перед сборкой пакета.
Любой объект непримитивного типа должен иметь только одного владельца.
Есть скалярные (целочисленные, float, bool, char/символьные) и составные типы (кортежи, массивы (он в стеке)).
Если выполняется компиляция в режиме отладки, Rust включает проверку на целочисленное переполнение, приводящую вашу
программу к панике. В режиме release выполняет обёртывание второго дополнения (256 становится 0, значение 257 становится
1).
Инструкция и выражение. Инструкция это объявление, а выражение выражается в результат какой-то.

graceful shutdown — корректное выключение. Если необходимо чтоб резкого прерывания не было. Внутренности завершились,
после выключилось.

1. Сразу остановит приём новых запросов по сети
2. Дождётся завершения всех уже выполняемых запросов
3. Завершит работу сервера

SIGTERM, если родительский процесс был завершён. Этот сигнал обычно отправляется программе либо когда завершается
операционная система, либо когда завершается родительский процесс программы.
SIGINT, если в консоли, где запущена программа, нажали Ctrl+C.
src/bin - создаются в нем сколько угодно других исполняемых главных файлов.
async-trait - вспомогательная библиотека позволяющая делать трейты асинхронными. Помогает писать без Pin<Box>.

Стек хранит значения в порядке их получения, а удаляет — в обратном. Это называется «последним пришёл — первым ушёл».
Все данные, хранящиеся в стеке, должны иметь известный фиксированный размер. Данные, размер которых во время компиляции
неизвестен или может измениться, должны храниться в куче. Куча устроена менее организованно: когда вы кладёте данные в
кучу, вы запрашиваете определённый объём пространства. Операционная система находит в куче свободный участок памяти
достаточного размера, помечает его
как используемый и возвращает указатель, являющийся адресом этого участка памяти. Этот процесс называется выделением
памяти в куче и иногда сокращается до выделения памяти (помещение значений в стек не считается выделением). Поскольку
указатель на участок памяти в куче имеет определённый фиксированный размер, его можно расположить в стеке, однако
когда вам понадобятся актуальные данные, вам придётся проследовать по указателю. Помещение в стек происходит более
быстро, чем выделение памяти в куче, потому что операционная система не должна искать место для размещения
информации — это место всегда на верхушке стека. Для сравнения, выделение памяти в куче требует больше работы, потому
что операционная система сначала должна найти участок памяти достаточного размера, а затем произвести некоторые
действия для подготовки к следующему выделению памяти. Доступ к данным в куче медленнее, чем доступ к данным в стеке,
потому что вам нужно следовать по адресу указателя, чтобы добраться туда.

Тип данных размер которых известен во время компиляции не требует .clone (). Нет разницы между глубоким и поверхностным
копированием. Поэтому две переменные могут жить. Если тип имеет типаж Copy, то автоматом копируется и поэтому не
перемещается (move). Rust не позволит нам аннотировать тип с помощью Copy, если тип или любая из его частей реализует
Drop.
Вот некоторые типы, которые реализуют Copy:

- Все целочисленные типы, такие как u32,
- Логический тип данных bool, возможные значения которого true и false,
- Все типы с плавающей запятой, такие как f64.
- Символьный тип char,
- Кортежи, но только если они содержат типы, которые также реализуют Copy. Например, (i32, i32) будет с Copy, но кортеж
  (i32, String) уже нет.

Крейт — это наименьший объем кода, который компилятор Rust рассматривает за раз. Крейты могут содержать модули, и модули
могут быть определены в других файлах, которые компилируются вместе с крейтом.
Крейт может быть одним из двух видов: бинарный крейт или библиотечный крейт.
Бинарные крейты — это программы, которые вы можете скомпилировать в исполняемые файлы, которые вы можете запускать. У
каждого бинарного крейта должна быть функция с именем main.
Библиотечные крейты не имеют функции main и не компилируются в исполняемый файл. Вместо этого они определяют
функциональность, предназначенную для совместного использования другими проектами. Под крейтом обычно понимается библ-ый
крейт.
Корневой модуль крейта — это исходный файл, из которого компилятор Rust начинает собирать корневой модуль вашего крейта.
Cargo следует соглашению о том, что src/main.rs — это корневой модуль бинарного крейта с тем же именем, что и у пакета.
Точно так же Cargo знает, что если каталог пакета содержит src/lib.rs, пакет содержит библиотечный крейт с тем же
именем, что и пакет, а src/lib.rs является корневым модулем этого крейта. Cargo передаёт файлы корневого модуля крейта в
rustc для сборки библиотечного или бинарного крейта.
Дерево модулей должно быть определено в src/lib.rs. Затем любые общедоступные элементы можно использовать в бинарном
крейте, начав пути с имени пакета. Бинарный крейт становится пользователем библиотечного крейта точно так же, как
полностью внешний крейт использует библиотечный крейт: он может использовать только общедоступный API.

### Заимствование и владение

Borrow-checker - механизм компилятора который отслеживает время жизни объектов.
Передача по ссылке объектов называется одалживанием (borrowing).
В любом месте кода для любого объекта может существовать либо только одна мутабельная ссылка, либо любое количество
немутабельных ссылок. "let r1 = &mut s; let r2 = & s;" - так нельзя.
Для примитивов, тк размер маленький и не владеют доп-ыми ресурсами, срабатывает копирование в местах смены владения.
Правила заимствования:

- В любой момент времени вы можете иметь либо одну изменяемую ссылку либо сколько угодно неизменяемых ссылок (но не оба
  типа ссылок одновременно).
- Ссылки всегда должны быть действительными.

borrow checker - средство проверки заимствований, обеспечивает соблюдение правил владения и заимствования.
Ошибка двойного освобождения - это когда один указатель вызывается несколько раз. Например:

```
{
    let s1 = String::from("hello");
    let s2 = s1;
} // происходит поверхностное копирование (без данных в куче), но в Rust-е это называется "перемещением"
```

Rust никогда не будет автоматически создавать «глубокие» копии ваших данных.

```
      let s1 = String::from("hello");
      let s2 = s1.clone(); // тут происходит глубокое копирование
```

Механика передачи значения функции аналогична тому, что происходит при присвоении значения переменной. Передача
переменной в функцию приведёт к перемещению или копированию, как и присваивание.

Чтоб не менять владельца и не владеть переменной, можно передать через ссылку, н-р: x (y: &String){}.
Заимствование - процесс создания ссылки. Взять в долг значение по ссылке и как-то использовать. Заимствование - это
взятие по ссылки на пользование. Владение это передать другому хозяину.
Нельзя иметь более одной изменяемой ссылки на значение. Преимущество этого ограничения заключается в том, что Rust может
предотвратить гонку данных во время компиляции. Гонка данных похожа на состояние гонки и происходит, когда возникают
следующие три сценария:

- Два или больше указателей используют одни и те же данные в одно и то же время,
- Минимум один указатель используется для записи данных,
- Отсутствуют механизмы для синхронизации доступа к данным.

Так же стоит проверка и на комбинирование ссылок:

```
    let mut s = String::from("hello");
    let r1 = &s; // no problem
    let r2 = &s; // no problem
    let r3 = &mut s; // BIG PROBLEM
    println!("{r1}, {r2}, and {r3}");
    // -----------------------------
    let mut s = String::from("hello");
    let r1 = &s; // no problem
    let r2 = &s; // no problem
    println!("{r1} and {r2}");
    let r3 = &mut s; // no problem
    println!("{r3}");
}

```

Висячие ссылки (не скомпилируется):

```
fn main() {
    let reference_to_nothing = dangle();
}
fn dangle() -> &String {
    let s = String::from("hello");
    &s
}
```

### Структуры и данные

String - имеет указатель на массив, длину и capacity, данные лежат в куче. Строка может быть изменяема, по сравнению
с go. Во время выполнения программы нужно запросить память в куче у ОС, и самое главное возврат этой памяти обратно.
Нам нужно соединить ровно один allocate ровно с одним free. Освобождение памяти осущ-ся после выхода из области
видимости. Rust сам запускает его drop.
String - является собственником буфера, в котором содержится строка. Это технически обертка няд Vec<u8>. Этот буфер
располагается в куче.
String реализует признак Deref, который возвращает &str. Поэтому через &String можно получить &str.

&str - строковый литерал, его содержимое известно на этапе компиляции, и он жестко прописан в исполняемом файле. И оно
не изменяемое!
&str - строковый слайс, который ссылается на буфер со строкой, но ни как не управляет этим буфером. Компилятор
помещает в сегмент данных/кода и там эта строка живет все время. Не занимается управлением памяти. Может принадлежать
сегменту данных, так и куче (если это изначально String) или даже располагаться на стеке. str — не Sized, а &str —
Sized. Известный и постоянный размер (указатель и длина).

В Rust есть только один строковый тип в ядре языка - срез строки str, обычно используемый в заимствованном виде как
&str.
Тип String предоставляемый стд. библ-ой Rust, не встроен в ядро языка и является расширяемым, изменяемым, владеющим,
строковым типом в UTF-8 кодировке.
Метод add (в String, не забирает во владение параметр, но внутри исп-ся self) в Rust используется принудительное
приведение (deref coercion), которое превращает &s2 в &s2[..].

enum - перечисления, каждая опция это "вариант".

Вектор - Rust должен знать, какие типы будут в векторе во время компиляции, чтобы точно знать сколько памяти в куче
потребуется для хранения каждого элемента.

Срез позволяет ссылаться на непрерывную последовательность эл-ов в кол-ции, а не на всю кол-ию. Срез явл. своего рода
ссылкой, поэтому он не имеет права владения.
Строковый срез - это ссылка на часть строки.
Структура (struct) — это пользовательский тип данных, позволяющий назвать и упаковать вместе несколько связанных
значений, составляющих значимую логическую группу. ::new () - ассоциированная ф-ия.
Кортежная структура - struct Color (i32, i32, i32);
единично-подобными структурами - struct AlwaysEqual;
Поле String в структурах можно определять с целью полноценности структуры. &str нужно будет объявлять через lifetime.
Примитивы по умолчанию реализуют трейт/типаж Display, т.к. там только одно значение. А в структурах надо явно задавать
Display.

Ссылка похожа на указатель в том смысле, что это адрес, по которому мы можем проследовать, чтобы получить доступ к
данным, хранящимся по этому адресу; эти данные принадлежат какой-то другой переменной. В отличие от указателя, ссылка
гарантированно указывает на допустимое значение определённого типа в течение всего срока существования этой ссылки.

Тип String является оболочкой над типом Vec<u8>.
Нельзя взять символ по индексу у String, н-р так s[0], из-за много-байтной кодировки.
Получение среза из строки нужно брать с осторожностью, н-р тут будет паника: &hello[0..1].
Конкатенацию удобно делать через макрос format!. Он не берет во владение.

```
for c in "Зд".chars() {
    println!("{c}"); // З, д
}
for b in "Зд".bytes() {
    println!("{b}"); // 208, 151, 208, 180
}
```

hash-map: let score = scores.get (&team_name).copied ().unwrap_or (0);
Если мы вставим в HashMap ссылки на значения, то они не будут перемещены в HashMap. Значения, на которые указывают
ссылки, должны быть действительными хотя бы до тех пор, пока хеш-карта действительна.

Дженерики можно указывать определенного типа: impl Point<f32>.

Основное предназначение сроков жизни — предотвращать появление так называемых "повисших ссылок" (dangling references),
из-за которых программа обращается не к тем данным, к которым она собиралась обратиться.
borrow checker (анализатор заимствований) - проверяет так же и времена жизни ссылок.
fn x (x: &'a str, y: &'a str) -> &'a - при равных a отдаст наименьший по времени жизни ссылки.
struct ImportantExcerpt<'a> { part: &'a str} - говорит что структура не может пережить свою внутреннюю ссылку.
В ф-иях может не требоваться срок жизн иссылок - по историческим причинам. Разрабы автоматизировали это дело. Это
называется "правилами неявного выведения времени жизни".
Времена жизни параметров функции или метода называются временем жизни ввода, а времена жизни возвращаемых значений
называются временем жизни вывода.
Все строковые литералы по умолчанию имеют время жизни 'static.

Замыкания в Rust - это анонимные функции, которые можно сохранять в переменных или передавать в качестве аргументов
другим функциям. Могут использовать значения из области видимости в которой они были определены. Не требует
аннотирования, соот-но далее можно подставить любой тип. Вычисляется на этапе компиляции. Но для другого типа после
выдаст ошибку, если например в начале использовали int, а потом String.
move - передать параметр во владение замыканию.

```
fn  add_one_v1   (x: u32) -> u32 { x + 1 } // обычная ф-ия
let add_one_v2 = |x: u32| -> u32 { x + 1 }; // замыкание
let add_one_v3 = |x|             { x + 1 }; // замыкание
let add_one_v4 = |x|               x + 1  ; // замыкание
```

Замыкания так же могут захватывать изменяемые ссылки.
FnOnce применяется к замыканиям, которые могут быть вызваны один раз. Все замыкания реализуют по крайней мере этот
трейт, потому что все замыкания могут быть вызваны. Замыкание, которое перемещает захваченные значения из своего тела,
реализует только FnOnce и ни один из других признаков Fn, потому что оно может быть вызвано только один раз.
FnMut применяется к замыканиям, которые не перемещают захваченные значения из своего тела, но могут изменять захваченные
значения. Такие замыкания могут вызываться более одного раза.
Fn применяется к замыканиям, которые не перемещают захваченные значения из своего тела и не модифицируют захваченные
значения, а также к замыканиям, которые ничего не захватывают из своего окружения. Такие замыкания могут выполняться
более одного раза и не меняют ничего в своём окружении, что важно в таких случаях, как одновременный вызов замыкания
несколько раз.

Итераторы - "ленивые". let mut v1_iter = v1.iter ();
Если мы хотим создать итератор, который становится владельцем v1 и возвращает принадлежащие ему значения, мы можем
вызвать into_iter вместо iter. Точно так же, если мы хотим перебирать изменяемые ссылки, мы можем вызвать iter_mut
вместо iter.

Rust выполняет разыменованное приведение, когда находит типы и реализации типажей в трёх случаях:

- Из типа &T в тип &U когда верно T: Deref<Target=U>
- Из типа &mut T в тип &mut U когда верно T: DerefMut<Target=U>
- Из типа &mut T в тип &U когда верно T: Deref<Target=U>

Не безопасный Rust (unsafe Rust) открывает доп-ые возможности. И за этот участок несет ответственность разработчик.
В небез-ом боке (unsafe{}) можно делать следующее (открываются супер-силы):

    * Разыменование сырого указателя
    * Вызов небезопасной функции или небезопасного метода
    * Доступ или изменение изменяемой статической переменной
    * Реализация небезопасного типажа
    * Доступ к полям в union

unsafe-блоки реком-ся делать маленькими.
Сырые указатели: *const T и *mut T. Звездочка это не разыменование, надо так и писать. Могут быть полезны для ЯП С.
В отличие от ссылок и умных указателей, сырые указатели:

    * могут игнорировать правила заимствования и иметь неизменяемые и изменяемые указатели, или множество изменяемых указателей на одну и ту же область памяти
    * не гарантируют что ссылаются на действительную память
    * могут быть null
    * не реализуют автоматическую очистку памяти

Создание сырых указателей и разыменование их в своем блоке:

```
let mut num = 5;
let r1 = &num as *const i32;
let r2 = &mut num as *mut i32;
unsafe {
    println!("r1 is: {}", *r1);
    println!("r2 is: {}", *r2);
}
```

Глобальная не изменяемая статическая переменная: static HELLO_WORLD: &str = "Hello, world!";
Доступ к неизменяемой статической переменной является безопасным.
Тонкое различие между константами и неизменяемыми статическими переменными заключается в том, что значения в статической
переменной имеют фиксированный адрес в памяти. При использовании значения всегда будут доступны одни и те же данные.
Константы, с другой стороны, могут дублировать свои данные при каждом использовании. Ещё одно отличие заключается в том,
что статические переменные могут быть изменяемыми. Обращение к изменяемым статическим переменным и их изменение является
небезопасным.
Любой код, который читает из или пишет в стат. изм. переменную должен находиться в unsafe блоке.

Макросы это доп. возможность Rust. Есть декларотивный макрос (macro_rules!) и три процедурных:

### Типажи

Типаж сообщает компилятору Rust о функциональности, которой обладает определённый тип и которой он может поделиться с
другими типами. Типажи тоже надо доп-но вводить в область видимости модуля.
Определение типажей - это способ сгруппировать сигнатуры методов вместе для того, чтобы описать общее поведение,
необходимое для достижения определённой цели.
Наш типаж можно указать для др. типа, потому что наш типаж явл. локальным. И мы может др. типаж указать для нашего типа,
т.к. тип явл. локальным. Но мы не можем указать внешний типаж для внешнего типа внутри нашего крейта! Это ограничение
называние согласованностью, или точнее сиротское правило (нет родительского типа).
Если у типажа есть реализация по умолчанию, то тип если ее переопределил, далее значит нельзя вызвать метод что был по
умолчанию.

```
// v1, такой способ объявления это для простых случаев
pub fn notify(item: &impl Summary) { // это синтаксический сарах для v2
    println!("Breaking news! {}", item.summarize());
}
но наверно лучше делать так:
// v2, такой способ для более сложных
pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}
```

Если возвращать типаж из ф-ии или метода, то тип должен быть одного вида.

Трейт является небезопасным, если хотя бы один из его методов имеет некоторый инвариант, который компилятор не может
проверить.

```
unsafe trait Foo {
    // методы идут здесь
}
unsafe impl Foo for i32 {
    // реализация методов идёт здесь
}
```

На структуру можно навешать N трейтов с одинаковым методом и структура тоже может его создать. Тогда вызывать надо так:

```
let person = Human;
Pilot::fly(&person);
Wizard::fly(&person);
person.fly();
```

А для ассоциативных ф-ий (без self) следующее: <Dog as Animal>::baby_name ().

Типаж Debug, PartialEq лучше ставить в структуры сразу, т.к. он может применятся в разных местах, н-р в assert_eq!.
Типаж PartialOrd только для типов, реализующих PartialEq.
Типаж Clone позволяет вам явно создать глубокую копию значения, а также процесс дублирования может вызывать специальный
код и копировать данные с кучи.
Типаж Copy позволяет дублировать значения копируя только данные, которые хранятся на стеке, произвольный код не
требуется.
Типаж Hash позволяет превратить значение произвольного размера в значение фиксированного размера с использованием
хеш-функции. Типаж Hash необходим в некоторых случаях. Например, для хранения ключей в HashMap<K, V>, для их более
эффективного хранения.
Типаж Default позволяет создавать значение по умолчанию для типа.

- trait A : B { ... } // Трэйт A "наследует" трэйт B
- Если компилятор видит что у объекта есть трейт Copy (trait Copy: Clone {}) (это играет роль пометки/маркера), то
  вызывается Clone (). У примитивов он есть, а у др. нет. Поэтому срабатывает copy-семантика. Если в структуру добавить
  трейт copy, то тогда move не будет происходить, а будет вызываться clone.

Трейты Deref, DerefMut позволяют получить условно оригинальную (не)мутабельную ссылку. Если они реал-ны в объекте, то
компилятор внутри вместо &obj подменяет на obj.deref (), так же и с deref_mut.

- trait Sync - маркерный трейт, можно читать из нескольких потоков можно безопасно использовать в разных потока.

### Умные указатели

Умные указатели - это структуры со своими данными. Имеют метаданные и возможности. Они часто владеют данными, на которые
указывают. Для них уже реализованы типажи Deref и Drop.
Box<T> для распределения значений в куче (памяти)
Rc<T> тип счётчика ссылок, который допускает множественное владение
Типы Ref<T> и RefMut<T>, доступ к которым осуществляется через тип RefCell<T>, который обеспечивает правила
заимствования во время выполнения вместо времени компиляции

Box<T> - умный указатель (размер известен):

- Когда у вас есть тип, размер которого невозможно определить во время компиляции, а вы хотите использовать значение
  этого
  типа в контексте, требующем точного размера.
- Когда у вас есть большой объем данных и вы хотите передать владение, но при этом быть уверенным, что данные не будут
  скопированы
- Когда вы хотите получить значение во владение и вас интересует только то, что оно относится к типу, реализующему
  определённый трейт, а не то, является ли оно значением какого-то конкретного типа

Box удобен для рекурсивного использования. Множественное владение этой ссылки не подразумевается.
Если компилятор не знает сколько выделить места для данных, то он выдаст ошибку. Поэтому надо знать ему размер всех
данных на этапе компиляции.
Пример рекурсивного списка:

```
enum List {
    Cons(i32, Box<List>),
    Nil,
}
let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
```

Обычная ссылка - это разновидность указателя, а указатель можно рассматривать как своеобразную стрелочку направляющую к
значению, хранящемуся в другом месте.
let x = 5; y = &x; *y - перейти к значению, на которое оно указывает - это и есть разыменование.
let x = 5; y = Box::new (x); *y - тоже получаем разыменование. Тут Box скопировал х, а не взял ссылку.
Если делать MyBox, то для разыменования для него реализовать типаж Deref. После компилятор будет знать как раз-вать.
*(y.deref ()) - defer () возвращает ссылку (чтоб не было перемещения в self), а после происходит разыменование.

Rc<T> - умный указатель для размещения данных в куче для чтения. Необходимо для множественного владения.
Ссылкой владеют несколько. Когда внутренний счетчик обнуляется, то данные удаляются. Используется в однопоточных
сценариях.
Использование Rc<T> позволяет одному значению иметь несколько владельцев, а счётчик гарантирует, что значение остаётся
действительным до тех пор, пока любой из владельцев ещё существует.
Позволяет обмениваться данными между несколькими частями вашей программы только для чтения данных. Не нарушает правила
заимствования.

```
let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
let b = Cons(3, Rc::clone(&a)); // не a.clone(), принятно Rc::clone.
let c = Cons(4, Rc::clone(&a)); // не a.clone()
```

Rc::clone - увеличивает внутренний счетчик. Не делает глубокого копирования.
В большинстве реализаций clone происходит глубокое копирование. А в Rc::clone нет.
Rc::strong_count (&a) - показывает кол-во ссылок. Сильные ссылки - это то с помощью чего вы можете поделиться владением
экземпляра Rc<T>.
Rc::week_count (&a) - Слабые ссылки не отражают связи владения, и их подсчёт не влияет на то, когда экземпляр Rc<T>
будет очищен. Они не приведут к ссылочному циклу, потому что любой цикл, включающий несколько слабых ссылок, будет
разорван, как только количество сильных ссылок для задействованных значений станет равным 0.
Когда вы вызываете Rc::downgrade, вы получаете умный указатель типа Weak<T>.
Он не использует примитивы многопоточности, чтобы гарантировать, что изменения в подсчёте не могут быть прерваны
другим потоком. Это может привести к неправильным подсчётам - незначительным ошибкам, которые в свою очередь, могут
привести к утечкам памяти или удалению значения до того, как мы отработали с ним.

RefCell<T> - единоличное владение данными, которые он содержит. Только для однопоточного сценария.
С помощью ссылок и типа Box<T> инварианты правил заимствования применяются на этапе компиляции. С помощью RefCell<T> они
применяются во время работы программы. Если вы нарушите эти правила, работая с ссылками, то будет ошибка компиляции.
Если вы работаете с RefCell<T> и нарушите эти правила, то программа вызовет панику и завершится.
Тип RefCell<T> полезен, когда вы уверены, что ваш код соответствует правилам заимствования, но компилятор не может
понять и гарантировать этого.

Вот список причин выбора типов Box<T>, Rc<T> или RefCell<T>:

- Тип Rc<T> разрешает множественное владение одними и теми же данными; типы Box<T> и RefCell<T> разрешают иметь
  единственных владельцев.
- Тип Box<T> разрешает неизменяемые или изменяемые владения, проверенные при компиляции; тип Rc<T> разрешает только
  неизменяемые владения, проверенные при компиляции; тип RefCell<T> разрешает неизменяемые или изменяемые владения,
  проверенные во время выполнения.
- Поскольку RefCell<T> разрешает изменяемые заимствования, проверенные во время выполнения, можно изменять значение
  внутри
  RefCell<T> даже если RefCell<T> является неизменным.

Можно изменять неизменяемые данные у RefCell<T>.
let value = Rc::new (RefCell::new (5)); // внутри не изменяемого можно изменить.
Mutex<T> - это thread-safe версия RefCell<T>

Mutex - это сокращение от взаимное исключение (mutual exclusion), так как мьютекс позволяет только одному потоку
получать доступ к некоторым данным в любой момент времени.
Блокировка - это структура данных, являющаяся частью мьютекса, которая отслеживает кто в настоящее время имеет
эксклюзивный доступ к данным.
let m = Mutex::new (5); let mut num = m.lock ().unwrap (); *num = 6;
После получения блокировки мы можем воспринимать возвращённое значение, как изменяемую ссылку на содержащиеся внутри
данные.
Вызов lock возвращает умный указатель, называемый MutexGuard, обёрнутый в LockResult.
Когда MutexGuard выходит из области видимости, то автоматически снимается блокировка.

Arc<T> является типом аналогичным типу Rc<T>, который безопасен для использования в ситуациях многопоточности.

Умный указатель представляет из себя класс, который не просто предоставляет доступ к данным по адресу, но и умеет
автоматически очищать память, на которую он ссылается.

- Box: фактически это просто безопасная обёртка над указателем. Конструктор Box::new (значение) переносит значение со
  стека в кучу и возвращает объект Box, внутри которого содержится указатель с адресом объекта в куче. Если размер на
  этапе компиляции не известен, то надо в Box.
- Rc (Reference Counted) - объект хранящий в себе ссылку на данные и ссылку на счетчик в куче. При клонировании
  копируются ссылки, счетчик увеличивается на 1. Когда выходит из скоупа, то счетчик уменьшается. При нуле идет отчистка
  данных из кучи. Он не реализует DerefMut, поэтому не может изменять данные.
- Cell<T> — обёртка, которая позволяет заменять своё содержимое целиком (не модифицировать), безопасно и атомарно. Но не
  позволяет получать мут. ссылку и получить не мут. ссылку которая стала бы не действительна при замене значения в Cell.
  Можно объявлять без mut, т.к. изменения происходят атомарно. Защиты от гонки данных у него нет.
- RefCell<T> - дает возможность модифицировать значение (часть) по ссылке. Не является потоко-безопасным.
  let ref_cell = RefCell::new (1);
  let mut mut_ref: RefMut<'_, i32> = ref_cell.borrow_mut ();
  *mut_ref = 5;
- Arc<T> (Atomically Reference Counted) - совместное владение данных которая потоко-безопастна. Arc не является
  синхронизированным, поэтому не позволяет менять своё содержимое. Обычно делают так: Arc<Mutex<UserSession>>.

### Каналы

Канал состоит из двух половин: передатчика и приёмника.
Канал считается закрытым, если либо передающая, либо принимающая его половина уничтожена.

```
use std::sync::mpsc;
let (tx, rx) = mpsc::channel(); // тут надо еще определить тип отправляемых данных, иначе не скомпилируется
```

mpsc означает несколько производителей, один потребитель (multiple producer, single consumer).

```
let (tx, rx) = mpsc::channel();
thread::spawn(move || { // переместили в другой поток tx с помощью move
    let val = String::from("hi");
    tx.send(val).unwrap();
});
let received = rx.recv().unwrap();
println!("Got: {received}");
```

Получатель имеет два важных метода: recv и try_recv.
recv () блокирует осн. поток, получает Result<T, E>. Когда канал закроется, то получаем ошибку от Result, тем самым
понимаем что канал закрыт.
try_recv () не блокирует осн. поток и сразу возвращает Result<T, E>. Это на тот случай если у осн. потока есть еще чем
заняться. А try_recv () можно поместить в цикл, для получения статуса.
Как отправили данные в канал, то после этот val уже не доступен в том потоке.

```
for received in rx { // Считывание данных с канала-приемника. Когда канал будет закрыт, итерация закончится.
    println!("Got: {received}");
}
```

Множество поставщиков у канала (multiple producer) делается через клонирование

```
let (tx1, rx) = mpsc::channel();
let tx2 = tx1.clone();
thread::spawn(move || {... tx2
thread::spawn(move || {... tx1
```

Каналы: в stdlib есть mpsc (multiple producers, single consumer). Многие треды могут записывать в него, но только один
читать. mpmc - много пишущих, много читающих. Channel (не буф.) и sync_channel (буф.). Почитать про
atomic https://marabos.nl/atomics/.

### Многопоточность

Стандартная библиотека Rust использует модель реализации потоков 1:1, при которой одному потоку операционной системы
соответствует ровно один "языковой" поток.
Когда основной поток завершается, то все порожденные потоки тоже закрываются, независимо от того, завершили они работу
или нет.

```
thread::spawn (|| {...}); // тут нет ожидания завершения данного потока
let handle = thread::spawn (|| {...}); handle.join().unwrap(); // ожидаем завершения потока в осн. потоке
```

В замыкание потока нужно аргументы передавать через move, чтоб компилятор точно знал сколько будет сущ-ть аргумент (ы).
«Не стоит передавать информацию с помощью разделяемой памяти; лучше делитесь памятью, передавая информацию».

Маркерный типаж Send указывает, что владение типом реализующим Send, может передаваться между потоками.
Маркерный типаж Sync указывает, что на тип реализующий Sync можно безопасно ссылаться из нескольких потоков.

- Потоки пользовательского пространства и неблокирующий API работают эффективнее, чем ОС-потоки и блокирующий API.
- tokio::select! - словно как match. Принимает N фьючеров, берет значение того кто первый отработал, остальное
  отбрасывает.
  let переменная = tokio::select! {
  шаблон_1 = фьючер_1 => выражение_1,
  шаблон_2 = фьючер_2 => выражение_2,
  };
  //----------------
  while let Some (msg) = tokio::select! {
  msg = rcv.recv ()                    => msg,
  _ = sleep (Duration::from_secs (1)) => None,
  } {
  println!("Received: {msg}");
  }
- Если используем Tokio, то нужно брать его Mutex, каналы и др., но не от ОС. Иначе код будет "тупить".
- tokio::sync::oneshot - канал в который можно послать только одно сообщение.
  let (snd, rcv) = oneshot::channel::<i32>();
  let _ = snd.send (1); // можно вызвать только однажды
  let r = rcv.await; // Ok (1)
- tokio::sync::watch - несколько могут отправить данные в канал, но читателям придет только последнее сообщение.
- В Tokio нет типа канала который позволяет множеству тасков отправлять сообщения и множеству читать их, но есть
  библиотека "async-channel", которая работает вместе с Tokio и предоставляет такой вид канала.
- Таски от Токио могут начаты в одном потоке ОС, а закончены в другом. Поэтому данные тасков должны быть Send. Однако
  есть инструкция которая задает правила отрабатывания в одном потоке - LocalSet::new (). LocalSet позволяет
  использовать
  типы не реализующие Send, в связи с этим можно использовать Rc, а не Arc.
